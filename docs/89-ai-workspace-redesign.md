# Fresh AI workspace redesign

The conversation layout in this record was subsequently replaced after user feedback; see [90-ios-glass-chat.md](90-ios-glass-chat.md). Scripted sample-sales data remains applicable.

## Behavior and scope

The previous assistant was below the first dashboard viewport, behind an expand icon, with small prompts and a composer detached from the first-use task. The user rejected that result and explicitly requested `user-expi` and `ui-design-index` design research.

Target: the owner/CEO reviewing company reports on desktop or mobile. Primary goal: find the assistant, recognize an appropriate question, edit it, inspect its period label, and understand the result. Usage frequency and user testing are unknown. This change is UI work; no AI provider or backend response generation is connected.

| Stage   | Information/action                                     | Likely hesitation                          | Feedback/recovery                                    | Success criterion                       |
| ------- | ------------------------------------------------------ | ------------------------------------------ | ---------------------------------------------------- | --------------------------------------- |
| Find    | AI assistant navigation; Ask Fresh AI dashboard action | Assistant hidden below fold                | Same named destination on desktop and mobile         | Visible route entry without scrolling   |
| Start   | Composer followed by six task prompts                  | Unsure what to ask                         | Examples fill the editable composer                  | Prompt selection does not auto-submit   |
| Context | Selected reporting-period label                        | Confusing label with attached records      | Explicit label-only explanation and toggle           | Date inclusion can be disabled          |
| Submit  | Enter or submit button; Shift+Enter newline            | Mistaking preview for live AI              | Offline status before action; honest response state  | No invented financial answer            |
| Recover | New conversation; report link                          | Losing the draft or finding an alternative | Focus returns to composer; actual report destination | Keyboard path and source reports usable |

Corrective finding: visual polish and visible AI branding cannot substitute for actual capability. An offline state must be visible before interaction; it must not first appear as a surprise after the user sends a question. No glowing online indicator or fake provider selector is used.

Fidelity map: Pabel's narrow navigation rail → Fresh AI context rail; selected AI location → explicit owner nav item; central mark and two-line type relationship → compact Fresh AI welcome; broad rounded composer with a separated utility row → period control, submit, preview status; 2×3 neutral prompt cards → six distinct reporting tasks. Existing global top navigation remains shared with the owner dashboard. No mascot, stock photo, decorative background or animation runtime is needed.

Palette: the reference's cool blue is an action accent against nearly neutral whites and gray borders. Preserve that hierarchy in light mode. Dark mode translates surface lightness into charcoal (#1f2023), inset (#1a1b1e), and raised gray, with lighter blue (#86b5ff) for readable emphasis. This is a low-saturation cool palette, avoiding competing hue signals. Continuous neutral borders contain cards; words and icons carry task categories. Lilac remains a chart comparison color on the overview, not a card-state background.

## Implementation

`/system/assistant` is an owner-only UI destination. The dashboard has an Ask Fresh AI action above the metrics and a clear entry card. The assistant has its own CSS module and focused state hook. New conversation clears the current in-memory questions/draft; no persistent chat-history claim is made. The empty and conversation states share the same composer; the latter keeps the input below an independently scrollable transcript.

Validation and rendered comparison will be recorded after browser inspection. No claim of improved task success is established by implementation alone; run an uncoached owner walkthrough: find AI, choose a collections question, change it, exclude the period, and identify whether AI is connected.

## Rendered comparison and verification

Inspected the first desktop render against the primary artwork before refining mobile and tablet. The result preserves the narrow rail, central welcome, composer above suggestions, and two-column three-row prompt composition. Kept the brand's existing top navigation, replacing the reference's full application sidebar with a smaller context rail. Unlike the earlier Finexa adaptation, the input is the central first-use action rather than a box at the bottom of a mostly empty modal. Final screenshots retained in `.local/ai-workspace-redesign/screenshots/`.

- Browser: 1440×1000 desktop in light/dark, 768×1024 tablet, 375×812 mobile, and 320×568 short mobile. Document and form show no horizontal overflow. Tablet navigation moves to the bottom rather than compressing the brand and labels. On short mobile screens the redundant welcome is hidden so the composer and submit remain visible above navigation. Mobile composer is 16px and includes the actual report-period date range.
- Measured computed colors, light / dark: composer text 15.57 / 14.56; placeholder and prompt detail 5.64 / 6.86; input boundary 3.06 / 3.58. Physical-display testing remains unverified.
- Prompt populates/focuses draft without submission; Enter previews; Shift+Enter adds a newline. Whitespace-only input cannot submit. Period disabled/excluded state does not attach the date label. New conversation clears draft and questions. Input, controls and transcript retain visible keyboard focus.
- Desktop dashboard Ask Fresh AI opens `/system/assistant`; selected nav is correct. Mobile bottom navigation provides Dashboard, AI assistant and Reports.
- Web TypeScript, Prettier for all changed files, scoped diff whitespace checks passed. Workspace tests: 3 passed, including owner access and denial for other roles carrying reporting grants. Final cleared-console mobile navigation pass: no console errors.
- No AI provider, production build, commit or deployment was performed. Preview status appears before submission and the reply state routes users to actual company reports.

## Scripted sales-response demo

Added `CeoSalesSummary.tsx`; sales/revenue questions now reveal a scripted October 2026 summary rather than the offline placeholder. The first suggested prompt opens this path. Unmatched questions offer a button to try the sample and retain the real report link.

The detail card extends the previously reviewed Oriel answer pattern (summary → calculation/detail → next disclosure) within the existing Pabel workspace. Neutral bordered card, blue weekly bars, staggered CSS reveals, and an expandable device table. Reduced-motion disables all reveals and bar growth. No new animation dependency, external service, or generated answer is involved.

Fixed sample facts: gross sales ₱1,248,000, 52 phones, average ₱24,000, prior month ₱1,040,000 (+20%). Weekly totals ₱264,000/₱288,000/₱312,000/₱384,000 reconcile to gross sales. The demo’s October period is fixed and independent of the optional report-period label on the question.
