# HR secondary workspaces use the COO design

The 2026-11-19 request explicitly preserves the HR dashboard and applies the existing COO design only to matching secondary screens. The existing COO task list/detail, recruitment composer/list, personnel directory, notifications and HR-action source components provide the matched references. No unmatched new surface was introduced, so external design research was unnecessary for this contained reuse.

HR now selects its independently owned COO-style task table and task detail instead of the older layouts. The HR label identifies the workspace; assignment and private review controls still depend on their original permissions. Recruitment selects the collapsible composer and matching empty/list presentation already used by COO. HR's native-select adapter now activates for its own role, giving request/status controls the same dropdown presentation and keyboard behavior. The HR review/request panel type roles match the COO task list headings. Personnel and notifications already use matching components and remain as inspected.

All implementation changes in this pass are confined to the HR secondary-page/component sources. No dashboard, HR workspace theme, shared shell or COO source was edited by this pass. Existing blue tokens and current authorization remain in effect. Other concurrent workspace edits changed dashboard files while verification was running; those were preserved rather than restored.

The controlling references were the existing COO source and rendered COO recruitment/task screens. Retained evidence is in `.local/hr-pages-20261119/`. The comparison preserves the source's spacing, table density, typography, composer disclosure and dialog arrangement, while keeping HR's blue theme and permission-limited actions. The previous oversized review headings and disabled HR custom-select activation were corrected.

Web TypeScript and three role-design isolation checks pass.
