## Implementation direction

Audience: COO scanning current records and opening work, with status/period
selection near the data it changes. Primary visual grammar remains the established
black/neutral shell; Beautiful UI supplies a scoped compact-filter relationship.
Green/lavender distinguish verified and pending records. Counts are not targets,
trends, payment-completion percentages or a representation of every payment status.

- Direct 3M/6M/12M radios replace a hidden period dropdown. Native radio keys and
  labels retain keyboard operation. An original neutral thumb follows selection
  using the existing velocity-preserving spring and reduced-motion support.
- Payment-record ring and explicit counts replace the old segmented rail. The ring
  includes verified and awaiting-review counts only, with an explicit scope label.
  Empty and unavailable values never create imaginary completion percentages.
- Task status count controls sit directly above the task list. All/status filters
  retain existing server filtering and exact counts. Remove duplicate dropdown.
  Active state uses label emphasis and a check, without persistent edge highlights.
- Task dialog DOM puts work content first and the 240px properties rail on the right.
  At narrow sizes the properties follow the form. This is the user's supplied
  screenshot correction; form behavior and authorization remain.
- Remove decorative colored side rules from COO GCash status/notices, HR decision
  record and monitor error. Preserve labels, semantic information and keyboard focus.
